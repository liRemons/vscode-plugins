# Remons Markdown 可视化编辑器（VSCode 插件）· 技术文档

> 一款基于 React 组件 **`remons-markdown-editor`** 实现的 VSCode Markdown **自定义编辑器（Custom Editor）** 插件。
> 打开 `.md` / `.markdown` 文件时，可用可视化工具栏 + 实时预览进行编辑，编辑结果自动同步回底层文本文件。

---

## 1. 背景与目标

需求清单：
1. 封装一个 VSCode 插件；
2. 支持 React 组件；
3. 支持 Markdown 文件编辑，编辑器内核通过 `npm i remons-markdown-editor` 引入；
4. 完成技术调研并输出本文档。

核心矛盾：`remons-markdown-editor` 是一个**运行在浏览器里的 React 组件**，而 VSCode 插件的扩展进程运行在 **Node 环境**，无法直接渲染 DOM/React。因此必须引入 **Webview**（VSCode 提供的嵌入式浏览器视图）作为 React 组件的运行容器，并在「扩展进程 ↔ Webview」之间建立消息通道，把编辑结果落到真实文件。

### 2.2 对外 API（读取自 `dist/index.d.ts`）

**入口导出**

```ts
export { MarkdownEditor } from '...';
export type { MarkdownEditorProps, MarkdownEditorRef } from '...';
export { useRegisterToolbar } from '...';
export type { ComponentSchema, DialogField, ImageUploadConfig, PreviewOptions } from '...';
```

**`MarkdownEditorProps`**

| 属性 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `value` | `string` | - | 受控模式内容 |
| `defaultValue` | `string` | `''` | 非受控初始内容 |
| `onChange` | `(value: string) => void` | - | 内容变化回调 |
| `showPreview` | `boolean` | `true` | 是否显示预览面板 |
| `fullscreen` | `boolean` | `false` | 是否显示全屏按钮 |
| `previewOptions` | `PreviewOptions` | - | 预览渲染配置（继承自 `RenderMarkdownProps`） |
| `uploadConfig` | `ImageUploadConfig` | - | 图片上传配置 |

**`MarkdownEditorRef`**：`getContent(): string` 获取当前内容。

**样式引入**：包导出映射 `"./style.css" -> "./dist/index.css"`，即 `import 'remons-markdown-editor/style.css'`。

### 2.3 关键结论
- 组件为 **ESM（`"type": "module"`）**，且带 `exports` 子路径映射，需使用支持 exports map 的打包器（本项目选用 **esbuild**）。
- 依赖 `antd` / `@ant-design/icons`，意味着 Webview 需支持内联样式与字体资源（CSP 需放开 `style-src 'unsafe-inline'`、`font-src`）。
- `useRegisterToolbar` 提供「自定义容器 / React 组件」注册能力，是「支持 React 组件」诉求的落地扩展点（详见 §6）。

## 3. 总体架构

```
┌───────────────────────────── VSCode 窗口 ─────────────────────────────┐
│                                                                        │
│  扩展进程 (Node, dist/extension.js)          Webview (浏览器沙箱)       │
│  ┌───────────────────────────┐   postMessage  ┌──────────────────────┐ │
│  │ CustomTextEditorProvider  │◀──────────────▶│ React App (main.js)  │ │
│  │  · 绑定底层 TextDocument   │   { command }  │  · MarkdownEditor    │ │
│  │  · 整篇 WorkspaceEdit 写回 │                │  · value/onChange 桥 │ │
│  │  · CSP / nonce / asWebviewUri│              │  · 输入防抖回写      │ │
│  └───────────┬───────────────┘                └──────────┬───────────┘ │
│              │ applyEdit                                  │ 渲染         │
│              ▼                                            ▼             │
│      TextDocument（脏标记/保存/撤销/热退出 由 VSCode 托管）  .md 文件       │
└──────────────────────────────────────────────────────────────────────┘
```

**设计选型：`CustomTextEditorProvider` 而非 `CustomEditorProvider`**
- `CustomTextEditorProvider` 直接绑定 VSCode 的 `TextDocument`，**脏标记、Ctrl+S 保存、另存为、撤销/重做、热退出（hot exit）全部由 VSCode 原生托管**；
- 扩展只需做两件事：① 把文档文本喂给 Webview；② 把 Webview 的编辑通过一次 `WorkspaceEdit`（整篇替换）写回 `TextDocument`。
- 相比自研文件读写 + `CustomEditorProvider` 方案，代码量更少、状态一致性更可靠。

## 5. 关键实现说明

### 5.1 消息协议（`src/messages.ts`）

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| Webview → 扩展 | `{ command: 'ready' }` | React 已挂载，请求初始内容 |
| Webview → 扩展 | `{ command: 'edit', text }` | 编辑器内容变化，请求写回文档 |
| Webview → 扩展 | `{ command: 'modeChanged', mode }` | 视图模式切换（`preview` / `edit`），用于更新菜单上下文 |
| Webview → 扩展 | `{ command: 'themeChanged', theme }` | 用户切换深/浅色主题，同步到 globalState 并广播 |
| Webview → 扩展 | `{ command: 'immersiveChanged', immersive }` | 用户切换沉浸式编辑，同步并广播 |
| 扩展 → Webview | `{ command: 'load', text, config }` | 首次加载内容 + 展示配置（含 `defaultMode` / `theme` / `immersive`） |
| 扩展 → Webview | `{ command: 'update', text }` | 外部改动（撤销/重做、磁盘变化）同步 |
| 扩展 → Webview | `{ command: 'setMode', mode }` | 标题栏按钮发起的视图模式切换 |
| 扩展 → Webview | `{ command: 'setTheme', theme }` | 命令 / 其他面板发起的主题切换 |
| 扩展 → Webview | `{ command: 'setImmersive', immersive }` | 命令 / 其他面板发起的沉浸式切换 |

### 5.2 扩展进程（`src/extension.ts`）
- **注册**：`window.registerCustomEditorProvider(viewType, provider, { webviewOptions: { retainContextWhenHidden: true }, supportsMultipleEditorsPerDocument: false })`。隐藏标签页时保留 Webview 状态，切回不丢现场。
- **安全**：`webview.options.localResourceRoots` 限定为 `dist/` 与 `media/`；HTML 使用 **CSP + nonce**，脚本只能通过 nonce 执行。
- **写回**：`applyEdit` 用整篇替换的 `WorkspaceEdit` 写回 `TextDocument`，内容与当前文档相同则跳过（避免制造空 undo 步骤）。
- **回环抑制**：由 Webview 主动编辑触发的文档变化，通过 `suppressNextDocumentChange` 标志跳过一次回推，避免 Webview 内容被重复刷新。
- **模式联动**：维护 `editorPanelsByUri`（uri → 面板），标题栏命令 `modePreview` / `modeEdit` 向目标 webview 发送 `setMode`；webview 上报 `modeChanged` 后更新上下文键 `remonsMarkdownEditorMode`，控制按钮显隐。上下文键 `remonsMarkdownEditorActive` 表示当前是否处于可视化编辑器。
- **主题 / 沉浸式联动**：主题与沉浸式选择写入 `globalState`（`remonsMarkdownEditor.theme` / `.immersive`），任一面板切换后通过 `broadcastToPanels` 广播给所有已打开面板，保持多个页签一致；命令 `toggleTheme` / `toggleImmersive` 在命令面板、编辑器右键与标题栏均可用。

### 5.3 Webview（`src/webview/main.tsx`）
- **单例 API**：`acquireVsCodeApi()` 在模块顶层调用一次（VSCode 限制）。
- **双模式**：
  - `preview`（默认）：用 `remons-render-markdown` 的 `RenderMarkdown` 只读渲染，不挂载 CodeMirror，左下角铅笔图标切换；启动时从 `highlight.js` 完整包注册全部语言（组件自带的 `languagesCommon` 仅 7 种）；
  - `edit`：`<MarkdownEditor value={text} onChange={handleChange} />` 可视化编辑（编辑 + 实时预览），左下角眼睛图标切回；悬浮按钮均为图标（铅笔 / 眼睛 / 太阳月亮 / 面板），`stroke=currentColor` 跟随主题变量。
- **主题切换**：所有颜色由 `<html data-theme="dark|light">` 下的组件库 CSS 变量驱动，默认 **dark**；`auto` 模式监听 `body` 的 `vscode-*` 类名跟随 VSCode 主题，并把结果同步给组件库 ThemeProvider（`localStorage['app-theme-mode']`）与 `vscode.setState`。
- **沉浸式编辑**：编辑模式下 `showPreview={config.showPreview && !immersive}`，开启后不挂载预览分栏，编辑器占满整个面板；状态同样持久化，跨文件 / 跨会话保留。
- **KaTeX 本地注入 / Mermaid CDN 放行**：组件库默认从 CDN 动态注入 KaTeX 与 `mermaid.min.js`。KaTeX 由 `katex-setup.ts` 预先挂到 `window.katex`，复用本地打包实例；Mermaid 则在 CSP 的 `script-src` 中放行 `https://registry.npmmirror.com`，由组件库运行时加载（需联网）。此外必须显式传 `isSlotMermaid`（组件库内部条件判断无默认值），并用 `defaultCollapsed={false}` 让图表默认展开而不是折叠成标题栏。
- **模式持久化**：切换后写入 `vscode.setState({ mode })`，webview 重建时优先恢复；首次加载使用配置项 `remonsMarkdownEditor.defaultMode`（默认 `preview`）。
- **防抖回写**：输入 150ms 防抖后再 `postMessage({command:'edit'})`，避免每次按键触发整篇 `WorkspaceEdit`。
- **echo 去重**：以 `latestText` 记录权威内容快照；外部推送 `load/update` 时更新快照，`onChange` 回调值若与快照相同则为回吐、跳过回写——无需依赖「组件是否会因 value 变化触发 onChange」的假设，更健壮。

## 6. 「支持 React 组件 / 自定义容器」扩展点

`remons-markdown-editor` 提供 `useRegisterToolbar(schema)`，可在编辑器工具栏注册自定义容器/组件（自动表单模式、容器弹窗模式、标签包裹模式）。示例（在 `main.tsx` 的 `App` 内、`<MarkdownEditor/>` 同组件中调用）：

```tsx
import { useRegisterToolbar } from 'remons-markdown-editor';
import { AlertOutlined } from '@ant-design/icons';

useRegisterToolbar({
  name: 'alert',
  label: '警告框',
  icon: <AlertOutlined />,
  fields: [
    { key: 'type', name: '类型', componentType: 'select', defaultValue: 'info',
      componentProps: { options: [
        { label: '信息', value: 'info' }, { label: '成功', value: 'success' },
        { label: '警告', value: 'warning' }, { label: '错误', value: 'error' },
      ] } },
    { key: 'content', name: '内容', componentType: 'textarea', defaultValue: '' },
  ],
});
```

> 当前工程为保证开箱即用未内置具体业务容器，接入时按需在 Webview 侧补充即可。

## 7. 构建与运行

### 7.1 环境
- Node.js ≥ 20（当前验证：v20.20.2 / npm 10.8.2）；
- npm 已配置淘宝镜像（安装依赖时使用 `registry.npmmirror.com`）。

### 7.2 常用命令

```bash
# 安装依赖（淘宝镜像）
npm install --registry=https://registry.npmmirror.com

# 类型检查（不产出文件，产物由 esbuild 生成）
npm run check-types

# 生产构建（压缩）：产出 dist/extension.js 与 dist/webview/{main.js,main.css}
npm run build

# 开发监听构建
npm run watch

# 打包为 .vsix（不含 node_modules，运行时依赖已被 esbuild 打进 dist）
npx @vscode/vsce package --no-dependencies
```

### 7.3 esbuild 双入口
| 目标 | 入口 | 产物 | format / platform | 说明 |
| --- | --- | --- | --- | --- |
| 扩展进程 | `src/extension.ts` | `dist/extension.js` | `cjs` / `node` | `vscode` 作为 external |
| Webview | `src/webview/main.tsx` | `dist/webview/main.js` + `main.css` | `iife` / `browser` | 打包 React/antd/CodeMirror，抽取配套 CSS |

Webview 构建中 `define` 了 `process.env.NODE_ENV` 与 `global`，兼容部分依赖对 Node 全局的引用（残留的 `process.*` 均被 `typeof process` 守卫保护，浏览器环境安全）。

### 7.4 本地调试
1. `npm install`；
2. VSCode 打开 `markdown-editor-extension` 目录；
3. 按 **F5**（配置见 `.vscode/launch.json`，预启动 `npm: watch`）打开「扩展开发宿主」窗口；
4. 在宿主窗口打开 `example/demo.md`，默认进入 **只读预览**（`priority: default` + `defaultMode: preview`）；左下角为图标按钮组（编辑 / 预览 / 主题 / 沉浸，悬停显示 tooltip）；标题栏另有预览 / 编辑、主题、沉浸图标与 `</>` 文本编辑器按钮。

## 9. 已知限制与后续路线

- **默认编辑器**：当前 `priority: default`，打开 `.md` / `.markdown` 默认进入只读预览（配置 `remonsMarkdownEditor.defaultMode` 可选 `preview` / `edit`）；预览 ↔ 可视化编辑通过 webview 内按钮 / 标题栏命令切换，与文本编辑器通过 `openSource` / `openPreview` 命令切换；用户也可在 `workbench.editorAssociations` 中把 `*.md` 改回 `default`。
- **大文件性能**：每次编辑为整篇替换 `WorkspaceEdit`，超大文档（数 MB）会有开销；后续可做增量 diff 回写。
- **图片上传**：`uploadConfig`（`uploadUrl` / `onUploadImage`）尚未接入插件设置，可后续通过 `contributes.configuration` 暴露并在 `load.config` 中透传。
- **主题联动**：已内置 `remonsMarkdownEditor.theme`（`dark` 默认 / `light` / `auto`），运行时切换会覆盖默认值并记忆到 `globalState`；antd 组件内部颜色仍由组件库 CSS 变量控制。
- **依赖体积**：Webview 包约 3.2MB（全量 highlight.js + KaTeX）；Mermaid 由组件库运行时从 npmmirror CDN 加载，首次渲染需联网，断网时图表不可用。
